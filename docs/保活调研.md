# 安卓保活调研（2026-11-13）

测试机：魅族 20 Pro，Flyme 10.0.2.0A，Android 13（API 33）。

## 现状：已经做了什么

| 手段 | 状态 |
|---|---|
| 前台服务（`specialUse`，常驻通知） | 已做 |
| 每轮用 `setExactAndAllowWhileIdle` 闹钟叫醒 + 检查期间持 wake lock | 已做；「闹钟和提醒」权限已允许 |
| 看门狗闹钟（服务没了就拉起） | 已做 |
| 开机 / 更新后自动启动（`BOOT_COMPLETED`、`MY_PACKAGE_REPLACED`） | 已做 |
| 引导用户：忽略电池优化、魅族手机管家允许后台运行、最近任务锁定 | 界面已有，**但测试机上「忽略电池优化」还没开**（`dumpsys deviceidle whitelist` 里没有本应用） |
| 保活记录（`files/rounds.log`，算最近 24 小时最长间隔） | 已做 |

## 实测：昨晚断了 13 小时 21 分，进程却没死

- 监控页「保活记录」：最近 20 小时成功 36 轮，最长间隔 13 小时 21 分。
- `dumpsys activity exit-info com.reviewmonitor`：02:17 到 15:39 之间**没有任何进程退出记录**；15:39 之后的退出全是装新包时的 `FORCE STOP`。
- 所以这段时间进程一直活着，只是没有一次成功的检查。**不是被杀，是被「停住」了。**
- 那段时间跑的还是旧版本（在 WebView 页面里发 XHR 取数）。今天 15:39 起换成了 Rust 直连，WebView 只在登录时存在。

可能的原因（还没区分开）：

1. **旧版本特有的**：熄屏后后台 WebView 的渲染进程和 JS 被暂停，导致检查一直卡着。新版本已经不经过 WebView，如果是这个原因，现在已经好了。
2. **Doze 断网**：本应用不在电池优化白名单里。按 AOSP，前台服务进程在 Doze 下仍可联网，但 Flyme 可能更严。
3. **Flyme 自己的冻结 / 闹钟推迟**：魅族的后台限制和华为、小米同级（dontkillmyapp），闹钟可能被推迟或拦截。

注意：昨晚那段手机大概率在充电，充电时不会进入 Doze，所以第 2 条的可能性不大。这一点还要再确认。

## 网上常见方案，逐个看

| 方案 | 结论 | 原因 |
|---|---|---|
| 前台服务 + 常驻通知 | ✅ 已做，基础 | 官方路线 |
| 忽略电池优化（`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`） | ✅ 要开 | 不受 Doze、App Standby 限制；Android 13 起 8 天不打开就进 restricted 桶，在白名单里的不受影响 |
| 厂商后台权限：手机管家 → 权限管理 → 后台管理 → 允许后台运行；最近任务锁定 | ✅ 要开 | 国产 ROM 上只有用户手动加白名单，前台服务才真正可靠；开发者侧没有已知的替代办法（dontkillmyapp） |
| 精确闹钟 `setExactAndAllowWhileIdle` | ✅ 已做 | 唯一能把手机从 Doze 叫醒的常规手段；厂商仍可能推迟 |
| WorkManager / JobScheduler | ❌ 不换 | 最短 15 分钟，Doze 里会被推迟，满足不了 3 分钟一轮 |
| 1 像素 Activity、无声音乐循环播放、双进程互相拉起、native 守护进程（fork / 文件锁） | ❌ 不做 | Android 8 以后大多失效；无声音乐耗电并抢音频焦点；容易被 ROM 判成恶意行为直接拉黑 |
| 账号同步（SyncAdapter）、无障碍服务 | ❌ 不做 | 同步周期 15 分钟起而且不准；无障碍服务属于滥用权限 |
| 厂商推送（魅族 Push：系统维护长连接，官方称到达率 99.9%） | 🔶 备选 | 推送通道本身最稳，但轮询就得挪到一台常开的电脑或服务器上，凭证要离开手机；还要申请魅族开发者账号。等手机上实在保不住再考虑 |

## 下一步：先查清原因，再对症下药

改动（只加观测，不改行为）：

1. 每轮记一条诊断日志（文件，保留 2 天）：闹钟实际什么时候响的、比计划晚了多少、请求结果（成功 / 网络错误 / 超时）、当时是否在 Doze、是否在充电。
2. 服务启动时读 `ActivityManager.getHistoricalProcessExitReasons`，记下上次进程是怎么死的。
3. 监控页「保活记录」里显示最近一次中断的原因。

实验（一次只改一个变量）：

- 第 1 晚：只开「忽略电池优化」，其余照旧；**不插电**、熄屏放一夜。
- 成功信号：rounds.log 里没有超过 8 分钟的间隔。
- 失败时按诊断日志分类：闹钟没按时响（系统推迟或冻结）、闹钟响了但请求失败（断网）、进程死了（看退出原因）。然后只补对应的那一项。
